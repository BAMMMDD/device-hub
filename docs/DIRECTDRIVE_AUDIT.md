# DirectDrive 再監査と実装引き継ぎ（2026-11-15）

最初の依頼は **P1：ライブ照明の開始・停止と照明の復元をワーカーで管理する**。その上に「ファームの背景＋必要なキーだけ PC で光らせる」レイヤーを載せる。現行の深度・ヒートマップ・キー強調・波紋は残す。この文書は [前回の全体監査](AUDIT_HANDOFF.md) と [ライブ照明の実装・既存実機記録](LIVE_LIGHTING.md) を補うもの。

## 現状と今回の修正

- `LightArea::direct_drive` と `PerfCaps::live_travel` で「ライブ」を出す。押し込み深さは HID ワーカー → UI、色の計算は `livefx::Engine`、送信は UI → HID ワーカー。設定画面を離れても動く。デモでは DirectDrive 送受信が no-op のため、設定や画面の挙動は見られるが LED の復元は確認できない。
- [XsyD ドライバ](../crates/devhub-hid/src/xsyd.rs) ではバックアップが全チャンク分成功するまで色を書き込まない。読み戻しの短い応答やチャンク違いも失敗とする。途中でフレーム送信に失敗した場合も試行したセルを追跡し、未確認の色は次回の差分判定で確認済みとみなさない。
- 復元が一部失敗したときは追跡と元の色を残し、成功を返さない。停止の失敗を UI に通知する。未使用エリアの停止では HID に何も送らない。ライブ中の設定の読み直しは、一時色ではなく退避したカスタム色を使う。アプリから構成を切り替えるときは先に元構成を復元し、復元失敗時は切替を送らない。切替と再読の最中は新しい DD フレームを受け付けない。
- [コマンドパレット](../crates/device-hub/src/palette.rs) に、別のデバイスやホームから使える「ライブライティングを停止」を追加。従来のプレビュー切替は、実機色の読み戻しが無く、選択エリアが DD 対応でライブ照明を使用していない場合に限って出す。

検証：Windows で `cargo test --locked --workspace` 53 件成功（通信失敗の回帰テスト3件を追加）。`cargo clippy --locked --workspace --all-targets` は成功、既存の HID example 3件に警告。`cargo build --locked -p device-hub` 成功。SU66 Max のデモでライブ開始、ホームに移動、コマンドパレットから停止、ライブタブに戻って「停止中」を確認。今回の変更は実機への書き込みで検証していない。

| **P1** | **停止後の復元とジョブ順序を保証できない。** [`store::worker`](../crates/device-hub/src/store.rs) は無制限キューからフレームと制御ジョブを取得し、`Shell::Drop` は停止を送って 80 ms 待つだけ。点灯色の取得や別の HID コマンドが遅い場合は停止まで進まない。`XsydDriver::Drop` の保険も `release_cells` → `cmd` で応答を待つ。実機記録の「ピンに自動タイムアウトがない」と合わせると、強制終了後まで復元を保証することはできない。 | **store / app**。フレームは最新 1 件を保持し、`Stop` で保留分を破棄。既に送信中のフレームが返った後、次のフレームより先に停止する。通常終了と backend 切替は停止完了または期限を扱う。復元失敗には「もう一度復元」を出す。停止の ACK はホスト側の復元処理結果であり、DD フレームの ACK とは区別。fake driver で遅延、混雑、連打、終了、復元失敗→再試行を検証。 |
| **P1** | **起動・再接続・別経路の所有者が混ざる。** [`fx_tick`](../crates/device-hub/src/pages/live.rs) はセッションが無い間は待つが、再接続した同じ ID の `dd_on=false` を「外部から停止」とみなす。セッションの `dd_on` が画面プレビューとライブ照明で共用され、古い `Msg::DirectDrive` の失敗で再開した表示を止め得る。構成切替はアプリ経由を保護したが、機器本体で構成が変わるケースは未検証。 | **store / live**。所有者（画面プレビュー／ライブ）と世代を明示。復元成功までは次の所有者に渡さない。再接続を既定で停止にするか自動再開を選べるようにし、復元中・待機中・エラーと本体が切断済みの場合を区別する。古い結果で現セッションを停止しないこと、P1 の退避色を P2 に書かないことを検証。 |
| **P2** | **読み戻しとライブストリームが同じ HID ワーカーを消費する。** ライティング画面の点灯色取得は最大 9 チャンク。深度取得は新しいサンプルの有無が UI へ伝わらず、UI の 33 ms 周期で最新値を繰り返す。ヒートマップは観測したしきい値通過の回数で、物理的な総打鍵数を保証しない。 | **livefx / worker**。`Engine` から `armed/rearm` をライフサイクル側へ移し、`計測→色計算→DD` をワーカーで実行。UI 表示の配信は間引く。読み戻しは利用者が画面で見るときだけ、負荷に応じて低頻度に。少なくとも無効時／静止ハイブリッド／波紋／全面更新の HID レポート数、フレーム遅延 p50/p95、停止時間、入力間隔を比較。まず 30 Hz で安定性を測り、レートを上げるのは測定後。 |
| **P2** | **ファームに任せるセルと、黒く光らせるセルを区別できない。** [`off_color`](../crates/device-hub/src/livefx.rs) と色が一致するかどうかでハイブリッドの送信対象を決めるため、黒を指定した強調や低輝度で丸められた色が透過扱いになる。キー強調は刻印文字列で照合するので、分割 Space の左右を独立に保存できない。 | **livefx / UI**。フレームの `None` をファームに任せる、`Some(Rgb::new(0,0,0))` を消灯指定とする。ユーザー選択はレイアウトの安定 ID で保存し、旧ラベルは移行時に展開。黒、背景色と同じ強調、左右の Space、旧プリセット移行をテスト。 |
| **P2** | **カスタム照明の読み出しにまだ部分成功がある。** [`read_lighting`](../crates/devhub-hid/src/xsyd.rs) は per-key チャンクの失敗を無視するので、再読やエクスポートの空欄が後の `write_per_key` で削除として扱われ得る。ライティング画面も空の実機色マップを未受信とみなし、全消灯時に数式近似へ戻る。 | **HID / UI**。取得済み空集合と未取得を別に表現。カスタム対応機の部分読み込みは失敗として前回確認値を保つ。全消灯、読み取り未対応、チャンク欠落、DD 中の再読と停止、ベース照明変更を区別してテスト。 |

## 機能案（実装順）

1. **MVP：必要なキーだけ光るゲーム用シーン。** 例：ファームの波を背景に、WASD は青で固定、押した移動キーにだけ短い波紋、右上に Caps Lock の状態。色の優先順位は「状態表示 → 押下反応 → 固定キー → ファーム背景」。まず固定キー＋波紋だけを組み合わせ、状態表示は次の段階。照明設定とは別の「ライブシーン」に保存し、プレビューから適用してもデバイスに永続保存しない。全画面共通の停止は今回のパレットを使う。
2. **手元の状態を光で知らせる。** 割り当て先を選べる Caps Lock／マイクミュート／既存のマウス低バッテリー表示。閾値をまたいだときだけ短く表示する設定を用意し、低バッテリーの値が不明なら消灯指定せずに表示を解除する。通知の優先度、低輝度、点滅なしを設定可能にする。
3. **ゲームごとのシーンと音の演出。** アプリのフォーカスに合わせたシーン選択は任意設定にし、常時バックグラウンド実行や自動開始の前に対象デバイスを表示する。音楽反応は Windows の出力音を用いたローカル処理として、明示的に選んだデバイスの信号だけを処理。フォーカス連動や音源なしでもシーン編集は使える。外部アプリ固有の連携は別タスク。

## 次のエージェントへの実装手順

1. `AGENTS.md` を読み、`store` の DD 部分を `dd_stream` 等へ分ける。薄い状態機械（停止中／稼働中／復元中／復元失敗）と最新フレーム枠を fake driver で先にテスト。キューの通常設定書き込み順を保つ。Area ID は `LightArea` から運び、UI は機種名に依存しない。
2. 停止と構成切替の E2E を先に完了。ログ用のカウンタを足した後にワーカー内の `Engine` に進む。既存の `live_travel` / `direct_drive` / `direct_drive_stop` で表現できる間は契約を増やさない。追加が必要なら契約は追加のみ、デモも更新する。
3. 設定ファイルの互換性を保ったまま MVP シーンを実装。`None` と黒が異なること、ファーム背景が固定キー以外で継続すること、停止で開始前のカスタム色とファーム照明に戻ることを受け入れ条件にする。
4. 実機検証は Web HUB と他の HID クライアントを閉じ、検証前の構成と照明を書き出して実施。通常停止・ウィンドウ終了・最小化中の継続・P1/P2 切替・抜き差しを順に確認する。テストで再現できる通信失敗は実機で無理に起こさない。ファームの復元と配信停止を別々に記録する。
