# LAMZU MAYA X V2 / LM20 監査 — 2026-11-17

対象は Device HUB の `e75c453` と [LAMZU Aurora v1.0.38](https://www.lamzu.net/#/project/items)。
[公式の機種定義](https://www.lamzu.net/Config/env-models.json) と、配布中の共通バンドル
`index-DxSz_fAU.js`、設定画面 `index-Bn9q780G.js` は、`analysis/` の保存済みファイルとバイト単位で一致した。
[公式製品名](https://lamzu.com/products/lamzu-maya-x-v2) は **LAMZU MAYA X V2**、Aurora の機種行は
**Maya X(LM20)**。旧 `37B0:001F` の「MayaX V2」は別リビジョンで、今回の対象外。

**判定：基本の読み出しは動作する。公式 HUB と同等とはいえない。** 優先修正は、不正または古い応答の拒否、
有効プロファイルが不明なときの書き込み禁止、ボタン割当の送信値の修正。

## 実機で観測した内容

今回の Windows には無線の `37B0:0048` のみが列挙された。有線は今回読み直せていないため、
比較には [有線の既存フレーム](../crates/devhub-hid/fixtures/lamzu/lm20-wired-active.txt) を用いた。
無線では Aurora と Device HUB を閉じてから、公式フレームの GET とアプリの `scan / driver / info / read` のみ実行した。

## 修正優先度と根拠

| 優先度 | 指摘 | 挙動と根拠 |
|---|---|---|
| P1 | 応答の照合と長さ検査が不足 | `lamzu.rs:30–87, 231–244, 748–769`。`cmd()` はグループとコマンドしか照合せず、target、プロファイル、ボタン番号、`7+a[4]` を確認しない。連続するボタン GET は同じグループ/コマンドなので、古い隣のボタン応答を採用し得る。短い DPI/ボタン応答はスライスで panic し得る。DPI count=0 を1に丸めるため、前回の p4 のような異常値を正常データへ変換する。GET/SET で照合フィールドを分け、長さ・範囲・要求との一致を検証し、書込結果は ACK だけで確定しない。 |
| P1 | プロファイル不明時に1番へ書き込み・初期化が可能 | `lamzu.rs:222–227, 803–804, 1009–1015`。通信エラーや不正な active ID を1に置き換える。別プロファイルを編集していた場合に1番を変更し、「このプロファイルを初期化」が処理対象でない1番を消し得る。active の取得を失敗可能にし、読み書きとも失敗を伝える。設定 UI は最後の正常状態を保持し、読み取りが失敗したプロファイルを書込不可にする。枠4個の表示と初期化済みの判定は別。 |
| P1 | ボタンの送信値が公式と異なる | `lamzu.rs:346–349, 395–396`。Aurora の `jM()` は DPI 循環/＋/−に type `7` + `[6]/[1]/[2]`、ロックに `[5,Xhi,Xlo,Xhi,Xlo]`、プロファイル/ポーリング循環に type `8/13` + `[3]`。現実装は DPI 切替に type `1` + `[20/18/19]`、ロックのYに `0,0`、循環に `[0]` を送る。既存コードとの互換入出力と、接続中 LM20 に送る公式フレームは分ける。 |
| P1 | 共有受信機をペア先の確認なしで MAYA X V2 と扱う | `registry.rs:181–194`、`lamzu.rs:105–122, 597–620`。`0048` は公式表の Maya / Maya M / Orcus V2 などと共通。今回の個体は MAYA X V2 と実測できたが、現ドライバは `GetDevicePID` を使わず、未接続・別機種でも同じ名前・caps・`supported=true` を返す。無線は受信機名を初期値とし、ペア先の VID/PID を確認してから製品名と caps を確定する。差し替え・再接続・無応答でも再判定が要る。 |
| P2 | 不完全な DPI 更新が残る | `lamzu.rs:836, 978–995` と `pages/mouse.rs:441`。アプリの X/Y 切替はフラグだけを変更するが、公式 `$2()` は切替時に段の X/Y も書き直し、OFF 時は Y=X。DPI ページの Y 欄は現在のフラグでなく機種の `xy_split` だけを見る。さらに一つの `DpiStages` が値→色→有効段の3コマンドなので後段失敗で先の書込が実機に残る。空リストは `clamp(1,5)` の後に範囲外アクセス。入力検証を先に行い、途中失敗は再読が必要。 |
| P2 | 公式と異なる範囲・依存関係 | `lamzu.rs:447–534, 807–889`。LM20 の有線と Orbital 8K は選択肢が 500/1000/2000/4000/8000 Hz。125/250 は対象外だがアプリで選択可。PAW3955 の LOD は 0.7/1.0/1.3/1.5/1.7 mm、デバウンスは 0–15 ms。アプリは余分な LOD とデバウンス 0–32 ms を出す。周波数コード `2/1/32/64/128` は **LM20 側の** `fM()` と一致。別メーカー向けの `uM()` を使わない。公式では競技モード OFF で 20K FPS を無効化、Glass Mode ON で LOD 編集を止めるが、アプリは独立して操作できる。 |
| P2 | 無線 LED の cap とオン・オフ処理 | `lamzu.rs:433–439, 683–708, 866–883`。DPI インジケーターは無線でも `A3` のため、Orbital 経由なら公開するという条件は誤り。受信機 LED の個別モードの GET は一致するが、マスター判定は実機で誤表示。Aurora は Orbital の ON に `SetLightness(1,profile,0,255)`、OFF に `SetLightEffect` の index `255` / mode `0` を使い、アプリは ON/OFF とも違う長さの `SetLightEffect`。今回 SET は未実行。 |
| P2 | マクロ割当を出すが中身を管理できない | `lamzu.rs:317–324, 386–393, 577–583, 795` と `overlay.rs:560, 901`。マクロを割当候補に出す一方、`macros: None`・常に空リストで編集・転送・削除は未実装。公式 `MacroI/II/III` は回数 / 離すまで / 再押下までを type `16/17/18` で区別するが、現実装は一律 type `16`、後二者を `254/253` に変換する。別プロトコルの表現を流用している。完全に扱えるまでは未対応として扱い、既存割当を別物として上書きしない。 |
| P2 | 無線の寿命管理・メタデータ | `lamzu.rs:132–176, 597–620, 1032–1037`。通知は同じ VID/PID の先頭 IF を選ぶため受信機が複数あると別個体のイベントを紐付け得る。公式の接続/切断通知 type 6 は無視。マウスが応答しなくても asleep/未接続にならない。FW の4バイト目は固定 `0` として表示。受信機 FW は読まない。将来 `0.0.x.y` が出れば誤表示する。 |

## 機能と名前の判定

| 公式での機能・名前 | Device HUB の現状 | 判定 |
|---|---|---|
| 製品名 `LAMZU MAYA X V2` / 機種行 `Maya X(LM20)` | `LAMZU Maya X V2`、有線 `maya-x-v2` / 無線 `lamzu-dongle` | 表記の差は軽微。製品名は大文字に寄せると公式と一致。無線は本当にペア先を識別し、内部モデルも一致させるべき（プリセット候補の検索は `info.model`）。 |
| `左クリック` / `右クリック` / `ホイールクリック` / `戻る` / `進む` | `Left` / `Right` / `ホイールクリック` / `サイド (戻る)` / `サイド (進む)` | 5個の物理スロットは一致。名称は「左クリック」「右クリック」に統一可能。DPI 切替の割当は物理ボタンの追加ではない。 |
| Motion Sync・直線補正・リップル | モーション同期・直線補正・リップル制御 | これらは別々の正しいコマンド。名称差のみ。 |
| `ハイスピードモード`（OFF 時）/ `競技モード`（ON 時）、`20K FPS` | `HyperMode`・`トラッキングモード (20K FPS)` | 前者は「競技モード」の方が役割を把握しやすい。「高速トラッキングモード」の説明は後者と混同させる。20K FPS はセンサーのスキャン、8K USB ポーリングとは別。 |
| `高速トリガー` / `Rapid Trigger` | `連打 (左ボタン)` / `連打 (右ボタン)` | **意味が違う**。公式は左右クリックの応答最適化で、意図しないダブルクリックの可能性を説明。自動連射は別のボタン割当 `X_Click`。磁気スイッチの押下深さ設定とも区別する。 |
| `デバウンスタイム`・`角度調整`・`SensorCenterOffset` | クリックデバウンス・センサー角度・センサーオフセット | 機能は概ね一致。公式のオフセット UI は −5～+5。`mm` は公式の画面コードからは確認できず、実距離とは断定しない。 |
| ホイール方向と `ホイール応答時間` | `B-hop (ホイール誤操作)`・`B-hop 時間` | 方向 0/2/3 と時間 200–1000 ms、200 ms 刻みは一致。「誤入力を抑止」と効果を断定する裏付けは今回取れていない。 |
| `AdaDPI`：速度と倍率のカーブ、プリセット、カスタム | `Adaptive DPI` の ON/OFF だけ | 部分対応。「カーブを編集できる」とは言えない。変更時に古いカーブを再送するため、応答の点数・長さを検証してから書く必要がある。 |
| スリープ 1/5/10/15/20/25 分 | 同じ分数 | 分数の候補は一致。公式が OFF と解釈する `0/0xFF00/0xFFFF` を現在は1分や大きな数に変換する。 |
| ボタン割当：無効、クリック、ホイール、キー+修飾、メディア、DPI、循環、マクロなど | 基本割当と一部メディア。LOD 循環・競技モード切替なし | 部分対応。公式の未対応コードを `Disabled`、未知のマウスコードを左クリック、未知のメディアを再生/一時停止と表示するため、設定の保存・復元時に置き換え得る。 |
| 本体の DPI 段色 / Orbital の受信機3灯 / 独立 RGB エフェクト | 段色と受信機3灯を表示、独立 RGB なし | 機能の分け方は正しい。段色 SET と LED マスター SET は今回未検証。独立 RGB を追加する根拠はない。 |
| プロファイル 1–4、初期化、受信機ペアリング・FW 更新 | 枠と初期化あり。LAMZU 固有のペアリング・FW 更新・更新通知なし | 枠数・一般機能としての出し方は妥当。実機で各枠が安全に切り替わるという意味ではない。FW 書込はこのアプリ全体の設計範囲と区別する。 |

既存の [プロトコル解析 §5](PROTOCOL_NOTES.md#5-lamzu-aurora-wwwlamzunet--maya-x-v2-lm20-実機検証済み) は、
有線の 64B feature、PAW3955、DPI の値と色が別、p4 の注意点、マクロの `u16BE slot`、受信機 PID の共有に関して今回の照合と整合する。
今回の **0048 経由での機種 ID／FW／基本設定の読み取り確認** を解析書にも追記した。受信機の書込みや復旧、DPI 色の変更、
Glass Mode の有効化、未初期化枠の書き込み、マクロ、現在のファームでの通知は今回試していない。

`cargo test -p devhub-hid --lib` は47件通過、`cargo check -p device-hub` と `cargo clippy -p devhub-hid --lib` も通過。
47件に LAMZU 固有の単体テストは含まれない。既存 `lamzuread` は途中で実機へ書き込み、失敗時に元値へ戻る保証がないので監査では実行していない。
製品コードと実機の設定は変更していない。
